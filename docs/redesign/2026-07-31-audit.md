# UI/UX audit, second pass

Branch `claude/macos-app-redesign-37c0a2`, on top of `679495a`.

Every finding below was reproduced in the running app. The captures are in [`2026-07-31/before/`](2026-07-31/before) (light) and
[`2026-07-31/before-dark/`](2026-07-31/before-dark) (dark), one per module, taken with:

```bash
open -n "$BUILT_PRODUCTS_DIR/Elephruit.app" --args \
  -ElephruitDevelopmentMode -ElephruitUseTemporaryStore \
  -ElephruitUseFixtureCalendar -ElephruitUseFixtureContacts -ElephruitUseFixtureReminders \
  -ElephruitFixturesAuthorized -ElephruitStartModule people -ElephruitAppearance dark
```

Two of those arguments are new, and exist because of what this audit ran into. The machine's screen
was locked for the whole session, so nothing could be clicked: navigation had to happen at launch.
And the calendar module could not be photographed in its working state at all, because the fixture
provider starts at `.notRequested` and reaching "authorized" meant a person pressing a button. That
is why the README has said, across several sessions, that the calendar has never been reviewed on
screen and dark mode has never been checked. **Both have now been looked at.** See commit `4e7933f`.

---

## Broken or confusing

1. **The list column is starved while the detail pane sits empty.** In a 1710-point window, Today
   lays the list out at ~330 points and gives the remaining ~1240 to a detail pane showing
   "Nothing selected". Titles truncate — "Send Maya the dog trai…", "Draft the announce…", "A note
   with a title long enough to n…" — with two thirds of the window blank beside them. This is the
   single most visible failure in the app and it is present in Home, Today, Upcoming, Inbox, Notes,
   Tasks, Projects, Areas, Bookmarks, Archive and Trash. `ModuleLayoutPolicy` declares a maximum for
   the detail column and nothing enforces it; the previous pass recorded this as finding 19 and
   fixed only the minimum.

2. **Trash offers to create things.** Every module without a selection shows the same empty state:
   "Nothing selected — Choose something from the list, or press ⌘N to make something new." In the
   Trash that is wrong rather than merely generic: ⌘N does not make anything there, and the sentence
   is an instruction to do something impossible. The same string appears in six modules.

3. **Overdue and due-today are the same colour in Tasks.** `Theme.Colors.overdue` is red and
   `dueToday` is orange, and the Tasks module paints "44 days late", "5 days late" and "Due today"
   all in orange. Today's list paints the same items' dates red. Two modules, two answers, and
   within Tasks nothing distinguishes six weeks late from due this afternoon.

4. **Two menu items own ⌘1.** `ElephruitApp.swift:285` binds Home with a literal
   `.keyboardShortcut(KeyEquivalent("1"), …)`, and `ShortcutCommand.goInbox` binds Inbox to ⌘1
   through the registry. `ShortcutRegistryTests` cannot see the collision because one side never
   enters the registry — which is precisely the failure the registry was built to prevent.

5. **"Import Files…" is registered as "Show Inspector".** `ElephruitApp.swift:223` attaches
   `.shortcut(.toggleInspector, …)` to the import command, so the shortcut editor in Settings offers
   to rebind "Show Inspector" and rebinds importing instead.

6. **Settings ▸ Advanced computes index statistics and cannot show them.**
   `refreshStatistics()` casts `services.search` to `DefaultSearchEngine`; the engine is an
   `FTSSearchEngine`, the cast fails, and the three `LabeledContent` rows are never rendered. Carried
   over unfixed from the previous pass's remaining list.

7. **An untitled note says the same sentence twice.** The row uses the body as a stand-in title and
   then prints the body underneath it, so "Rough thought with no title yet — the list shoul…" appears
   on both lines of the same row.

8. ~~**The People section index is not aligned to anything.**~~ **Withdrawn.** With the eight-record
   fixture the A–Z index appeared to drift out of step with the section headers. It does not: it is a
   jump bar and distributes the alphabet evenly down the column, exactly as Contacts does, which is
   only visible once there are enough records to fill it. Seeded to 400 it is correct.

   What survives is smaller and real: the index letters are drawn at the same size and nearly the
   same colour as the row subtitles, in the same plane, with no separation — so "B", "C", "D" read as
   stray characters inside the rows rather than as a control.

## Inconsistent

9. **Four row layouts for the same objects.** One task is drawn four different ways depending on
   where it appears: Today (checkbox · title · chip · date, right-aligned, subtitle beneath), Tasks
   (checkbox · title · flag, then a *second* line of glyph-prefixed metadata), Notes (icon · title ·
   chip, no date at all), Trash (icon · title, no metadata). The previous pass identified this as
   the largest remaining consistency problem and left it.

10. **Notes rows carry no date.** The most useful thing in a list of notes, absent — while Tasks
    shows five metadata fields per row.

11. **Time shows every control twice.** The sidebar has Period (Today / Yesterday / This Week / Last
    Week / This Month) and Grouped By (Day / Item / Project / Tag). The toolbar has a "Today" popup
    and an "Item" popup that set the same two properties. Both are on screen simultaneously.

12. ~~**"promise" is still the app's word.**~~ **Withdrawn.** The `promise` chip visible in the first
    captures came from a fixture store planted by an *older build*, before `TagConventions.owed`
    became `follow-up`. The source plants `follow-up` and has done since the previous pass. The store
    persists between runs and had simply never been re-planted — which is now fixable, and is why
    `-ElephruitLoadSampleData` exists.

13. **The search field renames itself.** "Search everything" in Notes, Today and Trash; "Search
    People" in People. Same control, same scope rules, two labels.

14. **The Calendar window is titled "Elephruit".** Every other module puts its own name in the title
    bar, and the calendar has a second toolbar row below the first, so the window carries two bars
    where the rest of the app carries one.

15. **A task's dates have two names on one screen.** The detail pane says "Start" and "Deadline";
    the inspector beside it says "Defer until" and "Due". Carried over unfixed.

## Visually weak

16. **People rows are 52 points tall**, against the design system's own `Size.rowHeightExpanded` of
    44. Measured at 1:1 against a 400-record library. The previous pass recorded this as "~80, near
    twice what it needs"; that figure was taken from a library so small that every row carried its
    own section header, and the header was being counted as part of the row. The overshoot is eight
    points, not forty.

17. **The person profile is a stack of oversized cards.** Ten quick facts, each a rounded card with
    a tinted icon chip, in the narrowest of the four columns.

18. **Empty-state actions are not the primary action they claim to be.** The previous pass's stated
    rule — an empty state's action is `.borderedProminent` and the default button — does not hold:
    Calendar's "Ask Again" and Time's "Add Time…" are both plain bordered buttons.

19. **An empty section header.** "Calendar Sets" is drawn with nothing beneath it.

20. **Unlabelled glyphs carry meaning.** A link symbol on every calendar row in Today, a sparkle in
    the Tasks toolbar, a currency glyph in the timer bar, three identical calendar glyphs for This
    Week / Last Week / This Month. None has a visible label.

## Accessibility

21. **State is carried by colour alone in the task lists.** "44 days late" and "Due today" differ
    only in a red/orange distinction that is currently not even applied correctly (finding 3).

22. **Tag chips are close to invisible in dark mode.** `quaternarySystemFill` behind caption text on
    the dark list background leaves the chip readable but its boundary indistinct.

23. **Dark mode is otherwise sound.** This is the first time it has been inspected. No literal colour
    survives anywhere — `SourceHygieneTests.coloursComeFromTheDesignSystem` has held — and every
    module renders correctly. The enforcement worked.

## Performance risk

24. **Nothing regressed, and the row work must not.** The People list is the constraint: any change
    to its row must stay layout-only. `ViewThatFits` measures every candidate on every row and must
    not enter that list; a per-row date formatter allocation must not either.

25. ~~**The fixture library is too small to prove anything.**~~ **Fixed while auditing.** Eight
    people could demonstrate neither a scrolling problem nor its absence, so every claim about this
    module's performance was an argument about code rather than a measurement.
    `-ElephruitPeopleCount 400` now seeds it. Two of the findings above were withdrawn on the
    strength of what that revealed, which is the argument for having done it.
